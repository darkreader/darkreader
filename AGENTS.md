# AGENTS.md

This file provides guidance for AI coding agents (GitHub Copilot, Codex, etc.) working in this repository.

## Repository Overview

This is a **local, privacy-focused fork** of [Dark Reader](https://darkreader.org/) — a Chrome/Firefox/Thunderbird browser extension that applies dark themes to websites dynamically.
All modifications preserve the core privacy principle: **no data leaves the user's machine**. No telemetry, no remote config fetches, no external API calls from the extension itself.

- **Runtime**: Browser extension (Chrome MV3 primary, Firefox MV2/MV3, Thunderbird)
- **Language**: TypeScript + TSX (UI via [Malevic](https://github.com/alexanderby/malevic))
- **Build**: Rollup + custom Node.js task runner (`tasks/cli.js`)
- **Tests**: Jest (unit), Karma (inject), Puppeteer (browser integration)

## Key Architectural Concepts

### Extension contexts

| Context                     | Entry point               | Notes                                           |
|-----------------------------|---------------------------|-------------------------------------------------|
| Background service worker   | `src/background/index.ts` | Handles fetch proxying, storage, tab management |
| Content script (ISOLATED)   | `src/inject/index.ts`     | Injects CSS/SVG filters, theme logic            |
| Content script (MAIN world) | `src/inject/proxy.js`     | Exposes plugin API to page JS                   |
| Popup UI                    | `src/ui/popup/`           | Settings panel, built with Malevic/TSX          |

### Cross-origin image fetching (CSP-safe pattern)

Pages like Gmail enforce strict `connect-src 'self'` CSPs. Dark Reader must **never** call `fetch()` from the content script context against cross-origin URLs. The correct pattern is:

1. **Cross-origin URLs** → route through `bgFetch()` in `src/inject/dynamic-theme/network.ts`, which sends a `chrome.runtime.sendMessage` to the background service worker.
2. **Background service worker** (`src/background/utils/network.ts` → `createFileLoader`) performs the actual `fetch()` and returns a `data:` URI.
3. **Same-origin URLs** → `fetch()` directly in the content script is fine.

`src/inject/dynamic-theme/image.ts` contains `loadBlobSafe(originalURL, dataURL)` which encapsulates this logic — always use or follow this pattern when loading external image resources from injected scripts.

### CSP configuration

- Extension page CSP is defined in `src/manifest-chrome-mv3.json` and generated by `src/utils/csp.ts`.
- `connect-src` for extension pages is `'self'` only — external fetches from extension pages must also go through the background.

## Privacy Constraints (must preserve)

- **No external network calls** from the extension UI or content scripts (all fetches via background service worker).
- **No analytics, telemetry, or crash reporting**.
- **No remote config or dynamic config loading** — all configuration is local.
- When adding new features that require loading external resources, always proxy through the background service worker using the `bgFetch` / `createFileLoader` pattern.

## Common Pitfalls for Agents

1. **Do not call `fetch(externalURL)` from content scripts.** Use `bgFetch()` instead. Violating this triggers `connect-src` CSP errors on strict pages (Gmail, GitHub, etc.).

2. **Do not call `loadAsBlob(url)` or `loadAsDataURL(url)` from `src/inject/` with cross-origin URLs.** These call `fetch()` directly. Use `loadBlobSafe()` in `src/inject/dynamic-theme/image.ts` as the model.

3. **Malevic is not React.** Event handlers are `onclick`, `onchange`, etc. (lowercase DOM names). The `m` import from `'malevic'` replaces `React.createElement`. There is no `useState`/`useEffect` — use Malevic's `setState`/`getState` from `'malevic/dom'`.

4. **MV3 background is a service worker** — no `XMLHttpRequest`, no persistent globals between activations. Use `chrome.storage` for persistence and `chrome.alarms` for deferred work.

5. **The `src/tsconfig.json` is the source of truth** for compilation — always type-check against it, not the root directory.

6. **Do not introduce remote URLs** into manifests, defaults, or config files. All resource URLs must be local (`chrome-extension://` or `data:`).
